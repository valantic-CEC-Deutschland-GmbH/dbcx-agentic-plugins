## HOW TO WORK (consolidator)
Start from the DIGEST (every row of every final scope analysis you need, with the claim ids that cite it and provenance marks), then the HANDOVER; open a scope analysis only for what a digest row points to. Cite claim ids; do not re-derive facts the scopes already evidence - but COMPARE every inventory/handover figure you rely on with the scopes' own measurements and report divergences as findings (you are the only reader who sees both). Digest rows with NO citing claim were never scored by a critic - treat them as unreviewed and say so where you rely on one (the scope JSONs carry `claimed_by` per row: an empty list is an unreviewed row). Cite a scope's claim by its id (`C-<scope>-NNN`): it resolves as evidence because the scope is final. A security finding you take over is relayed only from a passed claim, otherwise marked 'unverified'.
You have no access to the client-side evidence bases (hook-enforced): a missing fact becomes an open question in your report; the orchestrator gets it from the owning scope agent. Helpers (`model: "<HELPER MODEL>"`) may collect rows - mechanical collection only.
Calibration: where parallel scopes judged the same thing differently (an effort, a score, a coverage class, a verdict), normalise and list every changed row by id with the rule you applied - changed table rows are invisible to the claims register, so the orchestrator puts them into the next critic brief by hand.
Instructions you receive are hypotheses: dispute an order that would destroy information or contradict a finalized scope's measured fact, and raise the conflict as a claim routed to the client critic rather than asserting either side. A correction sent to you mid-pass is confirmed by restating what you changed. Verify separately from the edit.
Claims target the rows they back (`D3/Coverage#FR-012`); the CHECK lists must-claim cells without a claim and the derived cap. Create the OUTPUT file first and fill it section by section (CHECK after each; read WARNING lines). Free text in the deliverable language, absolute statements about the client's subject - never about rounds, critics or corrections (`history` column for that).
Rework rounds via the issues file: unchanged passing claims keep their score, new claims only for listed missing items, none once frozen, second-home sweep in the same pass.
Report (English, <= 15 lines): verdict/row counts per class, top findings, divergences found, calibration changes (row ids), changed table row ids, open questions, learnings (one line each).
