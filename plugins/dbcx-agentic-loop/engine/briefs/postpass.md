## POST-PASS TEXT CORRECTION - invariants
0. FILE is the only file you edit: the analysis Markdown. The register (`analysis/gauntlet/<scope>/claims*.md|json`), score files and round results are write-protected and frozen - reading the register tells you the scored wording, editing it changes nothing and is refused.
1. TEXT ONLY: the scope has passed; nothing is re-scored, no claim id is added, removed or renumbered, `status:` stays as it is, `round:` is NOT incremented.
2. Apply every item below. Rewrite each affected statement as an absolute, present-tense fact for the client - no 'corrected', 'round', 'post-pass', 'critic', 'analyst', 'orchestrator', 'session', no dates of edits, no earlier versions. Put the what/why/when of the change into the claim's `history` column (internal, not exported).
3. State the DISCRIMINATOR of every corrected figure (the rule a reader re-runs against a different file to get the same number), not just the number; a correction whose discriminator you cannot state is not ready - report it instead.
4. Sweep EVERY other home of each corrected fact in this file (Summary, rationale, table rows incl. verdict columns) - grep the old figure before and after - and run the CROSS-SCOPE SWEEP for figures other scopes may repeat; report cross-scope hits to the orchestrator (you do not edit other scopes).
5. Verify separately from the edit: after writing, re-read the file and assert the NEW text is present; run the CHECK command and read its output (OK with warnings is not OK). `dbcx postpass check` diffs your text against the SCORED register: every claim whose statement, evidence or target you changed needs a row in JUSTIFICATIONS (which item required it, why the scored proposition is unchanged, and how the critic's accept_if - the check prints it - is still met); a change that drops a figure, locator or id the accept_if relies on is refused and goes back to the orchestrator for a re-score. Never add a locator you cannot verify: the check lists every locator the register, the issues and the baseline do not contain as UNVERIFIED.
6. Report in your FINAL RESPONSE (English, <= 15 lines; you have no send operation, the orchestrator reads your final message): items applied / disputed with measurement, old-figure occurrences before/after, cross-scope hits, the postpass check verdict and its UNVERIFIED locators, and any hint you could not reproduce.
7. NO PEER VERIFICATION: you have no evidence access by design. Never message a critic or analyst to check a locator, count or line number for you (the hook denies your send operation) - list what you could not verify in your report; the orchestrator routes it to the role that owns the evidence.
