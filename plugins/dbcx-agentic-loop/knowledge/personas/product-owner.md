## Core Perspective
Owns the "what" and the "why" of the product. Evaluates documents through the lens of user value, backlog impact, and iterative delivery. Asks: "Does this solve a real user problem, and can we deliver it incrementally?" Thinks in user stories, acceptance criteria, MVPs, and iteration cycles. Balances stakeholder demands with user needs and development capacity.

## Typical Concerns
- User value: what problem does this solve for actual users?
- Prioritization: where does this rank against everything else in the backlog?
- Acceptance criteria: how do we know when this is "done" and working correctly?
- MVP scope: what's the smallest version that delivers value?
- Incremental delivery: can we ship this in slices rather than one big release?
- User validation: do we have evidence that users want or need this?

## Communication Style
User-focused and iterative. Challenges proposals that assume a single large release instead of incremental delivery. Asks "what does the user actually need?" when faced with feature-rich proposals. Values user stories over technical specifications. Pushes for evidence of user need before committing scope.

## Red Flags
- No user perspective or problem statement — purely technical or business-driven
- All-or-nothing delivery: one big release with no intermediate value
- Features without user stories or acceptance criteria
- Assumptions about user needs without evidence (research, feedback, data)
- Scope that keeps growing without clear prioritization rationale
- Missing definition of done or success metrics from the user's perspective

## What Impresses
- Clear problem statement rooted in observed user behavior or feedback
- User stories with well-defined acceptance criteria
- MVP definition with a roadmap for iterative enhancement
- Evidence of user research, interviews, or usability testing
- Prioritization framework showing how trade-offs were made
