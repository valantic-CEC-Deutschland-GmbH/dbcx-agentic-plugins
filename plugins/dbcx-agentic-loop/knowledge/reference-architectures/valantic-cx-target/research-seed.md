## Research topics – valantic CX Target-Architecture Standard

Open questions to resolve per engagement before the standard can be applied. Nothing here is a finding; every line is a question whose answer must come from the client with the source named (document, interface list, workshop statement and who made it) and the date. Every line is marked *(verify)*.

### 1. Canvas and scope
- Which systems are in the programme's scope (changed), which are context (drawn, unchanged), which are out of scope (listed only) *(verify)*
- Does an enablement layer (identity, CDN, consent, monitoring, tracking) exist as separately operated services, or is it embedded in the shop *(verify)*
- Which markets, brands and country-specific exceptions (local ERPs, local shops) must the storefront box carry as a list *(verify)*

### 2. Integration hub decision
- Does an integration platform, API gateway or event broker exist today, who operates it, and which flows already run through it *(verify)*
- How many systems and interfaces does the landscape have, and how many protocols and formats *(verify)*
- Which skills and team capacity exist to operate integration flows after go-live *(verify)*
- Which direct links exist today and why (latency, vendor connector, history) *(verify)*

### 3. Interface table
- Does an interface inventory exist, in which tool (Excel, Miro, CMDB), who maintains it, when was it last reconciled *(verify)*
- Per interface: direction, data objects, style, frequency, middleware, owner *(verify)*
- Volumes and peaks for the checkout, availability, pricing, login and order paths *(verify)*
- Which interfaces are manual today (exports, re-keying, e-mailed files), who performs them, how often *(verify)*

### 4. SSOT and decisions
- Declared master per data domain (product structure, enrichment, assets, price, stock, identity, account, profile, consent, order, content) with the document that states it *(verify)*
- Domains with more than one claimed master *(verify)*
- Which capability decisions are taken, which are open, who owns each open decision and by when *(verify)*
- Product versions and editions of the systems that stay *(verify)*

### 5. Views and roadmap
- The horizon and phases the roadmap must fit, and the external dates that constrain them (ERP upgrade, CRM rollout, warehouse changes, contract ends) *(verify)*
- Which data flows are critical enough for a zoom view (product, price, stock, customer and account, order, content) *(verify)*
- Which systems retire, and in which phase the last flow from each is replaced *(verify)*
