# adobe-commerce pack notes

- **Roles = `["target","source"]`.** Adobe Commerce is a platform a client plausibly runs today AND its source conventions are unambiguous: unit = module under `app/code/<Vendor>/<Module>` with `registration.php` (plus `etc/module.xml`), standard code under `vendor/magento`, activation in `app/etc/config.php`. Those are the anchors the spec names, so the source role is defensible.
- **No `adapter.py`.** The source role is therefore documentation-only: the pack can describe and review a repository, it cannot scan one until an adapter is written. Anyone who wants a real inventory run must implement `discover_units` over `app/code/*/*/registration.php` first.
- **Two API surfaces, deliberately.** `target_api_endpoint_families` mixes `graphql query:` / `graphql mutation:` entries with `/V1` paths because a fit estimation has to decide per requirement which surface carries it. The B2B entries are flagged `(B2B)` because they only exist on Adobe Commerce with the B2B module installed.
- **Edition is the first question, not a detail.** B2B, Content Staging, customer segments, dynamic blocks, Live Search and Product Recommendations are not all in Magento Open Source. A researcher must resolve edition + 2.4.x version + deployment model (Cloud Starter / Cloud Pro / on-premise) before any coverage verdict is meaningful.
- **Content model is a fork in the road.** Page Builder (HTML with `data-content-type` markup, one renderer per type in a headless frontend) versus the newer Edge Delivery Services storefront line are different content models. `content_model_name` is set to "Page Builder content type" because that is what an existing Adobe Commerce instance has; if the target is the Edge Delivery line, the content section of a D4 estimate has to be redone.
- **Not established here** and marked `*(verify)*`: the 2.4.x support matrix, per-edition feature split, the real GraphQL coverage for B2B operations, the PWA Studio Page Builder renderer set, the exact Cloud Starter vs Pro cron and mount limits, and whether SOAP is deprecated in the target release.
- Do not run: any `bin/magento setup:*`, cache or indexer command, `composer install/update` - listed in `as_source.do_not_run`.
