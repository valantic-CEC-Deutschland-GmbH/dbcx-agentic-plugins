# bigcommerce pack notes

- **Roles = `["target"]` only, and no `as_source` block.** BigCommerce is multi-tenant SaaS: there is no server-side shop code base to inspect. Customisation lives in apps (external services), Stencil themes, custom Page Builder widgets, the Scripts API and the Checkout SDK - none of which is a repository the plugin's source-side machinery could inventory. SaaS platforms whose extension model is apps/scripts are target-only.
- **No `adapter.py`**: there would be nothing for it to scan.
- **Three API surfaces are kept visible in `target_api_endpoint_families`.** V3 Management REST carries most admin resources, a few resources (notably orders and customer groups) are still V2, and the GraphQL Storefront API is the only browser-safe surface. Entries are prefixed `graphql storefront:` / `graphql admin:` where they are not REST paths. B2B Edition is listed as one entry because it is a separate API host with its own model.
- **The decisive architectural facts for a fit estimation** are that there is no server-side extension point, that rate limits are per plan, and that checkout customisation stops at Open Checkout / the Checkout SDK / embedded checkout. These are in `expected_blockers_d4` rather than only in the seed, because they change the shape of nearly every non-trivial requirement.
- **Content model.** `content_model_name` is "Page Builder widget". Widget INSTANCES are API-readable, widget RENDERING is a Handlebars template in the Stencil theme - so on a headless target every needed widget has to be reimplemented (Makeswift is the promoted alternative). This asymmetry is spelled out in `content_model_notes`.
- **Not established here** and marked `*(verify)*`: current plan names and sales thresholds; the exact API rate limits per tier; which resources are channel-aware for multi-storefront; the shipped Cornerstone/Page Builder widget set (the list in `target_content_component_types` is a best-effort seed); the current Catalyst and Makeswift support status; hosting regions and data residency.
- A researcher must resolve the plan tier and B2B Edition licensing FIRST - most coverage verdicts depend on it, not on the API reference.
